# DREX 공동 실무훈련 배포

## 현재 작업과 권한
기존 main 기준 `bf4d3ef` 위에 중앙 지도 연결, 행동 중심 실무훈련, 공동 접속 서버를 추가했습니다. 기존 3.x 실험 브랜치를 main으로 대체하지 않습니다. GitHub 연결의 브랜치 생성은 403 `Resource not accessible by integration`으로 거절되었습니다. 저장소 Contents 쓰기 권한이 있는 연결이 필요합니다. 환경 내 Vercel 인증과 Supabase 관리자 인증은 없습니다.

## 1. 코드 반영
GitHub 연결 권한을 수정한 뒤 변경 브랜치를 push하고 기존 main과 차이를 검토하여 병합합니다. 기존 main이 더 진행되었다면 먼저 최신 main에 통합해야 합니다. 제공 ZIP은 전체 소스 스냅샷이며 무조건 기존 파일 전체를 덮어쓰지 않습니다. 패치는 main `bf4d3ef`부터의 변경입니다.

## 2. 공동훈련 저장소 생성
기존 Supabase 프로젝트 SQL Editor에서 `migrations/001_practical_sessions.sql`을 실행합니다. 기존 테이블은 변경하지 않습니다. 새 테이블에는 RLS를 켜고 공개/일반 사용자 접근을 금지하며 서버 service_role만 사용합니다.

## 3. Vercel 환경변수
Production 및 시험할 Preview 환경에 다음 값을 설정합니다.
- `SUPABASE_URL`: 기존 프로젝트 주소
- `SUPABASE_SERVICE_ROLE_KEY`: 서버 전용 관리자 키. 브라우저 코드/공개 config/API 응답/GitHub에 절대 넣지 않습니다.
- `GROQ_API_KEY`: 기존 AI 공급자 키
- `GROQ_MODEL`: 선택 설정, 기존 값 유지 가능
기존 `SUPABASE_ANON_KEY`, `KAKAO_JS_KEY` 설정은 그대로 유지합니다. 새 서버 키는 `/api/config`로 반환하지 않습니다.

## 4. Vercel 배포
GitHub 연동 프로젝트의 Production Branch가 main인지 확인하고 병합 후 배포 완료를 확인합니다. 자동 배포가 꺼져 있다면 Vercel에서 해당 커밋을 배포합니다. 별도 build command나 프레임워크 변경은 필요하지 않습니다.

## 5. 운영 검수
1. 기존 홈페이지와 연습훈련이 열리는지 확인합니다.
2. `/practical/`에서 점검표를 적용하고 공동훈련을 개설합니다.
3. 다른 브라우저에서 초대 코드로 경찰 역할에 참여합니다.
4. 운영자가 통제 요청 → 경찰이 접수 → 두 화면에서 동일한 이력이 보이는지 확인합니다.
5. 경찰 계정에서 시간 진행·다른 기관 완료를 할 수 없는지 확인합니다.
6. 운영자가 시간 진행 및 선행 작업을 완료한 후 경찰이 완료 근거를 기록합니다.
7. AI 가이드가 실제 근거 번호를 반환하고 오류 시 기본 보고서가 유지되는지 확인합니다.
8. 종료 상태, 점검표 CSV, 보고서 HTML·인쇄, 백업 복원을 확인합니다.

## 운영 특성
- 초대 코드와 접속 토큰은 비밀로 공유합니다. 사용자 계정 기반 SSO가 아닌 세션 초대 기반입니다.
- 기관 하나에 담당 접속 하나를 배정합니다. 새로고침과 같은 탭의 최근 공동훈련 복귀를 지원합니다. 다른 기기로의 담당자 인계 기능은 아직 없습니다.
- 공동훈련 접근 유효기간은 생성 후 24시간입니다. 만료는 접근 제한이며 DB 자동 삭제를 의미하지 않습니다. 보관 정책은 기관이 정합니다.
- 서버가 기관 권한과 작업 조건을 재검증하고 버전 충돌을 감지합니다. 충돌 시 최신 내용을 확인한 뒤 다시 조치합니다.
- 저장이 불명확하면 자동으로 성공 처리하지 않습니다. 기록 확인 후 재시도해야 합니다.
- 지도 배치는 운영자 중심입니다. 지도와 실제 도로/침수 계산은 연결하지 않습니다.

## 되돌리기
문제가 발생하면 Vercel에서 이전 배포를 다시 활성화합니다. 새 실무훈련 저장소는 기존 훈련 저장소와 분리되어 있습니다. 롤백을 위해 기존 데이터나 신규 테이블을 삭제할 필요는 없습니다.

## 이번 검증 결과
- 엔진·서버 테스트 10개 통과.
- 독립된 브라우저 두 개에서 개설·참여·기관 권한·요청/접수·새로고침·종료 동기화·재접속 통과(임시 메모리 저장소).
- 기존 운영 AI API에 가상 샘플을 전송하여 HTTP 200 및 유효한 항목·근거 번호를 확인. 실제 응답은 `docs/practical-samples/AI_Guide_Actual_Response.json`에 보관.
- GitHub 브랜치 생성 API는 403으로 거절되어 업로드·Vercel 배포는 실행되지 않음. 실제 Supabase 저장소 검증도 미실행.
