- 기존 GitHub main 기준: `42a426ce610893fa116ac44e82e4dbbd0f60172c`
- 보존 브랜치: `archive/pre-command-sim-20260919`
- 신규 브랜치: `feat/drex-command-sim`
- 기존 index.html, practical/, API와 DB 스키마는 변경하지 않는다.

- 실제 서비스 교체·main 병합은 이 검증판 범위에 포함하지 않는다.

## 사용자 확정 요구
연습훈련은 항상 세부 가이드를 보면서 진행한다. 실제훈련은 대응 힌트 없이 같은 엔진으로 진행하며 사용법·역할 안내는 언제든 연다. 모드는 실행 중 변경하지 않으며 새 실행으로 시작한다. 실제훈련은 실제 재난 운영이 아니라 독립 판단을 하는 모의훈련을 뜻한다.

## 훈련 설계
대상: 시군구 상황실과 기관 연락관. 5개 역할(상황총괄, 소방, 경찰, 보건, 시설·대피지원) 및 통제자. 가상 호우, 지하차도 고립·요양시설 대피·도로 단절을 결합한다. 단양군은 향후 지역 데이터 팩이며 엔진을 특정 지역에 종속시키지 않는다.
목표: 정보공유, 공동 우선순위 판단, 자원경쟁 조정, 결과 확인 및 계획 수정.
평가: 정보 공유 시각, 요청 당시 보고 목록, 수락·지원 불가 사유, 결과 보고를 근거로 강평. 합격/불합격·점수는 산출하지 않는다.

## 모의 구조
순수 상태 전이 함수 `act`는 복제한 상태에만 명령을 적용한다. 초기 상태+명령 기록으로 결정론적 재생이 가능하다. 상태는 모델 버전으로 고정한다. 기관의 관측 보고와 전체 가상현장 상태를 분리한다. 요청은 담당 기관에서 수락해야 자원에 배정되며, 자원 점유 중에는 중복 배정할 수 없다. 통제자는 시간을 1~10분 진행하고 특정 기관에 추가 보고를 보낸다. 추가 보고가 물리 상태를 바꾸지는 않는다.

### 검증 전 교육용 규칙
고립 6명, 대피 대상 12명으로 시작. 소방 구조·이송팀 1대는 구조 또는 대피 한 임무만 수행하며 회당 최대 6명을 처리한다. 구조 이동/작업 5/5분, 대피 5/10분. 경찰 통제 3/2분. 도로 정비 4/6분. 의료 준비 0/5분. 12분 도로 단절, 해당 접근로를 쓰는 이동팀에 1회 우회 5분 추가. 정비팀은 별도 접근로를 사용한다. 진입 통제 전 5분마다 고립 2명이 추가된다. 같은 분에는 환경 변화 후 작업 완료 순서로 처리한다. 20분 이후 잔류 인원×분을 노출 비교 지표로 누적한다. 60분 종료.
완료 후 자원은 즉시 재배정 가능하다는 단순화가 있다. 복귀 동선·정밀 지형·수리수문·피로·병상 점유·의료 인계·치료 결과는 계산하지 않는다. 사상자 수를 예측하지 않는다. 실제 기관의 자원·소요시간 자료와 전문가 검토가 필요하다.

## 구현된 범위
- 한 기기 역할 전환, 연습/실제 모드, 상시 가이드
- 가상 상황도와 보고 출처·시각, 기관별 보고 공유
- 요청·수락·거절/대안, 자원 점유, 이동·작업, 도로 단절 영향
- 수동 시간 진행/종료, 추가 정보 부여
- 자동 로컬 저장, JSON 내보내기/검증 후 복원
- 종료 후 전체 강평, 요청 당시 정보, HTML 보고서
- 행동 직전 분기 재훈련과 이전 실행 보관/내보내기

## 명시적 한계와 다음 단계
현재는 한 기기 검증판이다. 역할 선택은 실제 인증·접근 통제가 아니며 서버 권한 분리가 필요하다. 여러 기기 동시 접속·채팅·기관 초대는 미구현. 클라이언트 데이터는 전체 상태를 포함하므로 정식 평가용 정보보안 경계가 아니다. 지도는 가상 개념도이며 실제 주소/항공지도 연계는 기존 지도 모듈을 차후 통합한다. 3D·CCTV·LLM은 아직 연결하지 않았다. 보고서는 규칙 기반 초안임을 표시한다.
다음 순서: 현업 모델 검토 → 서버 권한별 관측 투영과 동시 명령 처리 → 실제 지리 데이터·자원 이동 연계 → AI 보고 보조 → 선택 장면 3D. 새 화면을 기존 훈련과 연결할 때 단일 exercise ID와 동일 엔진을 사용하고 독립 DB를 무분별하게 늘리지 않는다.
