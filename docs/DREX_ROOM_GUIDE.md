# DREX 기관 공동훈련 사용 가이드

새 진입 주소는 `/command-room/`입니다. 기존 프로그램은 보존하며 새 버전은 `feat/drex-command-sim` 브랜치에서 관리합니다. `/command-sim/`도 새 진입 화면으로 연결됩니다.

## 참가자: 내 기관 업무에 집중하기

1. 개인 연습이면 본인 기관을 선택합니다. 합동훈련이면 통제자가 전달한 **본인 기관 전용 초대 링크**로 입장합니다.
2. 이름을 입력하고 입장합니다. 기관은 서버에서 고정되며 다른 기관으로 전환할 수 없습니다.
3. 우리 기관 상황보고와 받은 협조 요청을 읽습니다. 필요한 정보를 공동 상황판에 공유합니다.
4. 가용 자원을 확인하고 요청을 수락하거나 지원 조정·대안을 회신합니다. 직접 조치할 때는 판단 근거를 기록합니다.
5. 다른 기관 지원이 필요하면 해당 업무를 선택해 요청합니다. 상대 기관이 수락하고 작업을 완료하면 요청 내역에 결과가 도착합니다.
6. 완료 정보를 확인하고 다른 기관에 공유합니다. 훈련 종료 후 점검표와 보고서를 내려받습니다.

연습훈련은 상황별 다음 행동 가이드를 표시합니다. 실제훈련은 해당 가이드를 숨깁니다. 두 모드는 같은 시간·자원·권한 규칙을 사용합니다.

재접속은 같은 브라우저에서 가능합니다. 브라우저를 바꾸려면 미리 **내 접속코드 저장** 후 새 화면에서 불러오세요. 코드 파일은 해당 기관 권한이므로 공유하지 마세요. 훈련방은 24시간 유효합니다.

## 통제자: 합동훈련 개설

1. 합동훈련 개설에서 지역, 재난 유형, 시간, 훈련목표를 입력합니다.
2. 시나리오 자동 생성을 실행하고 내용·교육용 가정을 검토합니다. 수정 후 훈련방을 개설합니다.
3. 13개 기관별 초대 링크를 각각 해당 참가자에게 전달합니다. 하나의 링크를 모든 기관에 배포하지 않습니다.
4. 참가자가 입장하면 시작합니다. 미참여 기관 자동 대응을 끄면 13개 기관 모두 입장해야 시작됩니다.
5. 필요하면 특정 기관에 추가 상황을 부여하고 시간을 정지·재개합니다. 통제자는 기관의 조치를 대신 수행하지 않습니다.
6. 종료 후 전체 기관의 기록과 점검표를 확인합니다.

13개 기관은 예시 참여 구조입니다. 법정 13개 협업기능과 일대일로 같다는 뜻이 아닙니다. 현재 기관당 한 참가 세션이며, 계정 기반 SSO·복수 담당자·기관명 편집은 후속 개발 범위입니다. 초대 링크는 전달받은 사람이 입장할 수 있는 권한 링크입니다.

## 생성·시뮬레이션·평가 범위

- 지역·집중호우/침수 또는 화재·훈련시간·훈련목표로 교육용 시나리오를 자동 구성합니다.
- GROQ_API_KEY가 설정되면 AI가 상황 설명을 작성합니다. 실패하거나 키가 없으면 규칙 기반임을 명시합니다. AI는 실제 발생 사실을 조회하지 않습니다.
- 기관의 자동 대응은 규칙 기반입니다. 실제 참가자와 구분하며 참가자가 있는 기관의 결정을 대신하지 않습니다.
- 구조·수송·의료·도로·대피소·기반시설 등 기관별 대표 업무 하나를 모델링합니다. 모든 실무 업무를 구현한 것이 아닙니다.
- 시간, 자원 점유, 출입 통제 지연에 따른 추가 고립, 도로 단절에 따른 지연, 대피소 수용 여력을 연계합니다. 수치는 교육용 가정이며 실제 재난 예측 모델이 아닙니다.
- 배경지도는 실제 지도이며 훈련 지점은 가상 위치입니다. 일반지도는 광역 확인용입니다. 실제 CCTV 연결은 포함하지 않습니다.
- 점검표는 정보 공유·판단 근거·기관 협조·결과 공유의 공통 4항목을 기록과 대조합니다. 공식 평가점수나 생성형 AI 평가로 표시하지 않습니다.
- 보고서는 확인된 근거와 검토 필요 항목을 담은 HTML 초안 및 JSON 기록입니다. 기관 공식 서식·사용자 지정 평가점검표 업로드는 아직 지원하지 않습니다.

## 서버와 배포

Vercel API `/api/command-room`은 기존 Supabase `practical_sessions` 테이블의 JSON payload를 사용합니다. 새 payload 버전은 `DREX-ROOM-1`이며 기존 훈련 데이터와 구분합니다. 필요한 환경 변수:

- `SUPABASE_URL`: 기존 테이블이 있는 프로젝트 주소
- `SUPABASE_SERVICE_ROLE_KEY`: **같은 프로젝트**의 서버 전용 service_role 또는 호환 secret 키
- `GROQ_API_KEY`: 선택 사항, 시나리오 설명 생성용
- `GROQ_MODEL`: 선택 사항

키는 Vercel 환경 변수에만 설정하며 저장소·HTML·대화에 붙여 넣지 않습니다. Production 및 Preview 적용 범위를 확인하고 재배포합니다. health 응답이 503이면 공동훈련이 준비된 것이 아닙니다. 화면은 연결 오류와 개인 연습 대안을 표시합니다.

2026-09-20 확인 당시 기존 운영 API는 Supabase 서버 키 인증 실패(503)를 반환했습니다. 브랜치 배포가 성공해도 이 설정을 복구하기 전 외부 공동훈련 개설·입장은 사용할 수 없습니다.

### 로컬·교육장 시험 서버

Node.js 24 이상에서 저장소 루트 기준:

```sh
node command-room/dev-server.mjs
```

`http://127.0.0.1:8772/command-room/`을 엽니다. SQLite 기본 저장 위치는 `/tmp/drex-command-rooms.sqlite`이므로 장기 보존하려면 `DREX_ROOM_DB`를 별도 파일 경로로 지정합니다. 교육장 내부망 시험은 `DREX_BIND=0.0.0.0` 설정 후 해당 컴퓨터 주소로 접속합니다. 이 개발 서버를 인터넷에 직접 공개하지 않습니다.

서버 없는 개인 연습은 `command-room/preview.html`을 엽니다. 공동 접속은 지원하지 않으며 브라우저에 저장됩니다. 지도 배경은 인터넷 연결이 필요합니다.

### 검증

```sh
node --test tests/command-room.test.mjs
python command-room/build-local.py
```

`tests/command-room.browser.cjs`는 Playwright와 실행 중인 로컬 서버가 필요합니다. 별도 통제자·소방·경찰 세션에서 요청·수락·완료·공유, 재접속, 기관별 보고서, 모바일 넘침, 서버 없는 개인 연습을 확인합니다. 브라우저 기능 시험에서는 외부 지도 요청을 차단하므로 지도 타일 연결 여부는 별도 확인해야 합니다.

권한 테스트는 13개 기관 입장, 타기관 조치 차단, 비공개 정보 범위, 초대 링크 오용 차단, 동시 요청 CAS 재시도·중복 처리 방지, 시간 진행·중지, 점검표 범위 및 AI 연결 실패 전환을 검증합니다. 대규모 부하, 조직 SSO, 감사로그 보존정책, 공식 평가표 적합성은 검증 범위 밖입니다.
