# 온톨로지 기반 AI 시나리오 생성 아키텍처

## 목표

재난훈련 데이터를 단순 검색자료가 아니라 재사용 가능한 관계형 지식으로 전환하여, 훈련조건에 맞는 시나리오를 근거 기반으로 생성하고 증폭한다.

## 처리 단계

### 1. 지식 수집

기존 저장소의 협업기관, 임무, 자원, SOP, 평가항목, 컨설팅 지적사항을 출처와 함께 수집한다.

### 2. 정규화

기관명과 재난유형을 표준 ID로 통합하고, 같은 의미의 표현을 동의어로 연결한다. 예: `경찰청`, `경찰서`, `경찰`은 상황에 맞는 조직계층을 보존하면서 공통 기능 `교통·인파 통제`에 연결한다.

### 3. 온톨로지 연결

각 데이터는 다음 질문에 답할 수 있도록 연결한다.

- 어떤 재난과 지역특성이 어떤 위험을 발생시키는가
- 위험을 누가 먼저 인지하는가
- 어느 기관이 어떤 조치를 수행해야 하는가
- 어떤 조치가 먼저 끝나야 하는가
- 조치 지연이 다음 상황에 어떤 영향을 주는가
- 완료 여부를 무엇으로 입증하는가
- 어떤 평가항목과 연결되는가

### 4. 시나리오 조립

입력조건에 해당하는 하위그래프를 가져와 `재난 시작 → 연쇄 위험 → 기관별 정보 → 공동업무 → 의사결정 → 결과` 순으로 조립한다.

### 5. 시나리오 증폭

하나의 기본사건에 다음 증폭축을 선택적으로 결합한다.

- 위험강도
- 기반시설 장애
- 취약계층
- 자원 부족
- 기관 간 책임 충돌
- 정보 지연·오류
- 시민·언론 반응
- 수습·복구 압력

증폭은 관계가 확인된 경우에만 허용한다. 임의의 기관이나 장비를 추가하지 않는다.

### 6. AI 문장화

생성형 AI에는 전체 데이터가 아니라 선택된 하위그래프와 출력규칙만 전달한다. AI는 상황카드, 기관 브리핑, 통제관 진행문, 결과보고서 문장을 작성한다.

### 7. 검증과 승인

로컬 검증기는 다음을 확인한다.

- 모든 업무에 수행기관이 있는가
- 모든 선행업무가 존재하는가
- 모든 상황정보에 수신기관이 있는가
- 모든 기관에 최소 한 개 이상의 업무가 있는가
- 모든 의사결정에 두 개 이상의 대안이 있는가
- 모든 평가항목에 확인 가능한 행동근거가 있는가

구조검증을 통과해도 훈련책임자의 내용 승인을 거쳐야 실행 시나리오가 된다.

## 서비스 연결 계약

시나리오 생성 API 입력 예시:

```json
{
  "location": "서울 도심 A구역",
  "disasterType": "urban-compound-disaster",
  "regionFeatures": ["underground-space", "transport-hub", "dense-population"],
  "level": "intermediate",
  "durationMinutes": 30,
  "participants": ["seoul-city", "fire", "police", "metro"],
  "trainingObjectives": ["request-response", "life-safety", "information-sharing"],
  "randomSeed": "seoul-demo-01"
}
```

출력은 `scenario-generator.mjs`가 생성하는 구조를 사용한다. 시뮬레이션 화면은 `roleBriefs`, `injects`, `tasks`, `evaluationCriteria`만 읽으면 된다.

## 데이터 신뢰수준

| 상태 | 의미 | 사용범위 |
|---|---|---|
| candidate | AI 또는 자동추출 결과 | 검토화면에서만 사용 |
| curated | 기존 저장소에서 의미를 확인해 정리 | 교육용 시나리오 초안 |
| verified | 담당 전문가가 출처와 내용을 승인 | 실제 훈련 설계에 사용 가능 |
| official | 공식 매뉴얼·평가기준 원문과 버전 확인 | 해당 기관 승인 범위에서 사용 |

현재 v0.1 지식은 `curated` 수준이다.
