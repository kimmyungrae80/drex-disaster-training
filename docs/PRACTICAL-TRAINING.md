# DREX 기관 행동 중심 실무훈련 고도화

기존 A/B/C 엔진을 보존하고 `/practical/` 화면을 추가했습니다. DREX 기존 훈련 화면 상단에서 진입합니다. 기존의 `full`/`quick` 저장값과 처리 로직은 유지하고 선택 버튼에 연습훈련임을 표시합니다. 별도 평가관 모드는 추가하지 않습니다.

## 실무자 사용 순서
1. 실무훈련 화면의 훈련명·기관을 입력합니다.
2. 점검표 탭에서 기본 샘플 또는 사용자 JSON/CSV를 확인하고 적용합니다. 훈련 시작 후 기준은 고정됩니다.
3. 훈련을 시작하고 기관 역할을 선택합니다. 요청 → 담당 기관 접수 → 훈련시간 진행 → 완료 근거 입력 순으로 조치합니다.
4. 구조 완료에는 도로 통제와 전력 안전 확인이 선행되어야 합니다. 각 작업의 샘플 소요시간도 경과해야 합니다.
5. 전화·구두 조치는 외부 근거로 추가한 뒤 점검 항목에서 기록 번호를 연결합니다.
6. 종료 후 평가 초안을 검토합니다. 확인 필요 항목은 0점이 아니며, 해당 없음은 적용 배점에서 제외합니다.
7. AI 평가 가이드를 선택적으로 요청합니다. AI 응답의 항목·근거 번호를 검사하며, 제안은 판정을 바꾸지 않습니다.
8. 개선과제 담당·기한과 종합 의견을 작성하고 보고서 HTML/MD, 점검표 CSV를 내려받습니다. 보고서 HTML은 브라우저 인쇄로 PDF 저장 가능합니다.

## 샘플링
`가상 샘플 불러오기`로 18분간의 고정 사례를 불러옵니다. 정상 완료 3개, 지연 완료 1개, 요청 후 미완료 1개, 기록 미확인 1개입니다. 확인된 항목 67.5/85점, 적용 배점 100점, 확인 필요 1건이며 최종 총점으로 표시하지 않습니다.
- 보고서: `docs/practical-samples/DREX_Sample_Report.html`
- 점검표: `docs/practical-samples/checklist.json`

## 설계 범위
- 단독 역할 전환과 기관별 공동 접속을 지원합니다. 공동 모드는 별도 practical_sessions 테이블과 서버 환경변수 설정 후 사용할 수 있습니다.
- 13개 기관 역할에서 보완 기록을 남길 수 있으며, 가상 침수 시나리오의 작업 6개는 5개 핵심 기관에 배정됩니다.
- 시계는 수동 +1분. AI 대기·브라우저 대기는 점수 또는 상황 시간에 포함되지 않습니다.
- 임의 인명피해 또는 복구시간 예측을 생성하지 않습니다. 작업시간·기한은 검증 전 훈련 가정입니다.
- 자동 평가 초안은 연결 작업의 이행·기한 기반입니다. 복잡한 서술 기준은 실무자 검토가 필요합니다.
- HWPX·DOCX·PDF 점검표 자동 추출, 임의 재난 시나리오 편집, 도로 거리·침수 물리 모델, 실제 CCTV 연결은 포함하지 않습니다.
- 지도는 기존 command-map iframe과 기관 상태·배치 저장을 연동합니다. 외부 지도/검색 서비스 가용성에 의존하며, 배치 위치는 작업시간을 변경하지 않습니다.
- 상태는 `drex_practical_v1`로 브라우저에 별도 저장. 기존 `drex_ttx`는 건드리지 않습니다. JSON 백업과 형식·근거 검증을 거친 복원 UI를 제공합니다.
- AI는 기존 `/api/generate`와 서버 API 설정을 사용. 실패 시 규칙 기반 점검·보고서를 계속 사용합니다. AI 응답은 SSE 성공·실패 모의 응답과 기존 운영 API의 실제 가상샘플 요청으로 검증했습니다(HTTP 200, 반환 항목·근거 번호 유효). 실제 공동훈련 DB 연결과 신규 코드의 Vercel 배포는 권한·설정 후 확인이 필요합니다.

## 검증
`node --test tests/practical.test.mjs`
역할·상태 전이·선행조건·작업시간·근거 검증·미확인 점수 제외·사용자 기준·도움말 이력·수동 시계를 확인합니다.
브라우저에서 샘플 실행, AI 모의 성공/실패, 보고서 다운로드, 새로고침 복원, 역할 제한, 모바일 가로 넘침을 확인했습니다. 외부 지도 타일과 검색의 정상 제공은 검증 환경 네트워크에 따라 확인되지 않을 수 있습니다.

## 배포
기존 Vercel 라우팅에 `/practical/`과 정적 모듈/CSS 경로를 추가했습니다. GitHub main 병합 및 Vercel 배포는 별도이며, 로컬 구현 완료는 서비스 반영을 의미하지 않습니다.

## 공동훈련 검증과 배포
`node --test tests/practical.test.mjs tests/practical-service.test.mjs`로 엔진·서버를 검증합니다. `tests/practical-live.browser.cjs`는 임시 메모리 저장소와 서로 독립된 브라우저로 공동 접속을 검증합니다. 실제 Supabase 검증을 대체하지 않습니다. 구체적인 배포 순서는 `docs/DEPLOY-PRACTICAL.md`를 참고하세요.
