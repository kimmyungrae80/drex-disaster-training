# AI 재난훈련 시나리오 생성 연구 프로토콜

상태: 구현된 도구를 이용한 **예비실험 계획**. 실제 AI 비교 결과나 전문가 평가 결과를 보고한 문서가 아니다.

## 연구 질문과 주장 범위

가제: **다기관 재난대응훈련을 위한 온톨로지 제약 기반 AI 시나리오 생성 및 검증 프레임워크**.

- RQ1: 같은 기본 조건에서 추가 근거의 제공 여부가 생성 초안의 구조·내부 관계 오류에 어떤 차이를 만드는가?
- RQ2: 동일한 근거 사실을 필드 경로형 문장 또는 중첩 관계 구조로 표현할 때 결과가 달라지는가?
- RQ3: 동일한 검증 오류를 1회 피드백했을 때 수정 효과, 추가 시간·토큰 비용은 어떠한가?

현재 구현은 JSON-LD 자료를 이용한 제한된 사례 생성기이며 범용 논리 추론, 보고서 학습, RAG, 학습자 훈련 효과를 입증하지 않는다. A/B/C 모두 동일 검증기를 사용하므로 이 비교만으로 검증기 유무의 효과를 분리할 수 없다. 그 효과를 주장하려면 별도의 사전 정의된 절제실험이 필요하다.

## 지식 준비와 승인

1. 현재 54개 노드의 상태는 모두 `curated-unverified`이다. 원문 출처가 있는 것처럼 인용하지 않는다.
2. 공식 매뉴얼·훈련보고서 원문을 확보하고 문서 버전·발행기관·문서 위치·페이지 또는 절을 노드와 관계별로 기록한다.
3. 기관별 수행업무, 선행관계, 위험사건과 기대조치, 평가기준을 분야 전문가가 대조한다. 변경 이력과 검토자를 남긴다.
4. 합의된 지식을 동결하고 JSON-LD·시드 해시 및 실행 커밋을 기록한다. 내부 일치율과 독립 전문가 평가를 별도 결과로 보고한다.

`training-data.json`의 1,915건 메타데이터는 원문 학습자료가 아니다. 문자 깨짐·빈 원문 경로·중복 표시는 별도로 정제해야 하며 이번 생성기의 학습량이나 사례 수로 세지 않는다.

## 비교 조건

| 조건 | 공통 입력 | 추가 근거 |
|---|---|---|
| A 일반 생성 | 목적·지역명·30분·기관·필수 업무/사건 ID와 이름·평가기준 | 없음 |
| B 문장형 근거 | A와 동일 | 업무·기관 소유·선행업무·완료근거·평가 연결·상황 시각/수신/기대업무를 필드 경로형 문장으로 표현 |
| C 온톨로지 구조 근거 | A와 동일 | B와 같은 사실을 중첩 JSON으로 표현 |

B/C의 `factsSha256`이 같음을 확인한다. 이는 근거 사실의 동일성 확인이며 입력 토큰 수의 동일성을 뜻하지 않는다. B는 일반 문서 검색도 자연문장형 보고서 원문도 아니다. 구조화 경로 자체가 문장에 남아 있으므로 B/C 차이는 **직렬화·표현 형식** 수준의 비교로 해석한다. 프롬프트 길이와 공급자 반환 토큰 사용량을 함께 보고한다.

A도 업무 이름·기관·평가기준을 제공받는 제한된 생성 조건이다. 완전히 정보가 없는 일반 LLM과의 비교로 설명하지 않는다. 온톨로지에서 가져온 정답 관계가 내부 검증 기준이기도 하므로 C의 내부 일치율만으로 현장 정확성이 우수하다고 결론 내리지 않는다.

## 표본과 실행

현재 시드는 서울 도심 지하공간 침수 **하나의 사례 계열**이다. 초급·중급·고급 각각 3회 반복하고 A/B/C로 생성하면 27개 출력이 계획된다. 이는 27개의 독립 재난사례가 아니다. 지역명이나 반복 식별자를 바꿔도 새로운 재난사례로 세지 않는다.

CLI는 난이도·반복 블록마다 A/B/C 순서를 순환 배치한다. 3회 반복에서는 각 조건의 순서 위치가 균형을 이룬다. 반복수가 3의 배수가 아니면 완전한 순서 균형은 보장되지 않는다. 실제 연구에서 사례 범위를 넓힐 때는 사전에 사례 선정 기준과 사례별 공통 입력을 확정한다.

- 동일 공급자·모델·temperature 0.2·최대 출력 토큰 12,000·JSON 출력 설정을 고정한다. gpt-oss 모델은 코드에서 reasoning_effort를 low로 설정한다.
- 모델의 실제 응답 이름·응답 ID·호출 시간·토큰 사용량·종료 사유를 확인한다. 공급자가 설정이나 모델을 지원하지 않으면 실패로 기록하고 대체 모델로 섞지 않는다.
- 시드는 규칙 기반 골격과 선택지 순서를 고정한다. 공급자 LLM 샘플링 시드로 전달되지 않으며 AI의 완전 재현성을 보장하지 않는다.
- 웹 보정 기본값과 CLI 예비실험은 보정 없음이다. RQ3은 별도의 균형 조건으로 전부 보정을 켜서 수행하고 초안과 보정 결과를 분리한다. CLI의 현재 일괄 계획은 RQ3을 자동 구성하지 않는다.
- 최초 JSON 파싱 실패·항목 누락·API 실패도 보존한다. JSON 실패는 내용/구조 실패로 포함한다. API 실패율은 따로 보고하고 재시도 규칙을 사전에 정한다.
- `eligibleForModelComparison`은 전송 종류·모델 일치·호출 실패를 검사하는 보조 플래그다. 전문가 승인, 자료 완전성, 무작위화 적절성을 보장하지 않는다.

## 기록 단위

각 실행은 `runId`, 실행 버전, 선택 조건, 지식 해시, 소스 커밋(설정 시), 요청/실제 모델, 프롬프트와 해시, 요청 설정, 근거 해시, 원문 응답, 파싱 결과, 오류 목록, 소요시간과 토큰을 보존한다. `attempts[0]`이 최초 초안이다. `attempts[1]`은 보정 시도이며 실패할 수도 있다. `final`만으로 결과를 집계하지 않는다.

현재는 웹 브라우저 최근 10건 또는 CLI JSONL로 저장한다. 서버 공동연구 DB 저장은 구현되어 있지 않다. 원본 파일을 보관하고 보정 전후 자료를 수정 없이 분리하여 분석한다. 모의 응답(`transport: mock`)은 연구 표본에 포함하지 않는다.

## 측정 항목

| 구분 | 지표 | 해석 |
|---|---|---|
| 초안 구조 | 파싱 성공률, 필수 항목 충족률, 구조 검사 통과율 | 최초 응답 기준, 실패 포함 |
| 내부 관계 | 기관 배정·선행관계·평가 연결 불일치, 순환·없는 참조 | 동결한 내부 지식 기준 |
| 시간 | 범위 초과·상황 순서 위반 | 현장 시간 적정성과 구별 |
| 실용성 | 전문가의 내용 타당성·협업 판단·현장 적용 가능성 | 독립 평가 필요 |
| 편집 부담 | 승인 가능한 대본까지의 수정시간·실질 수정 수 | 편집 지침과 중단 기준 사전 정의 |
| 비용 | 호출 지연, 토큰 사용량, 보정 횟수 | 공급자 실패와 분리 |

오류가 많을수록 긴 출력에 불리할 수 있다. 항목별 오류 수와 검증 대상 기회 수를 함께 제시하고 비율의 분모를 사전에 고정한다. 구조적 완전성과 문장 품질을 하나의 임의 점수로 합치지 않는다.

## 전문가 평가 계획

- 가능하면 지식 작성자와 다른 재난대응 분야 평가자 2인 이상이 독립 채점한다.
- 평가용 자료는 생성 방식·모델·검증 결과·프롬프트를 가리고 동일 양식으로 정리한다. 블라인드 ID와 원 실행 ID의 매핑은 연구책임자가 별도 보관한다. 현재 자동 블라인드 내보내기는 구현하지 않았다.
- 역할 적합성, 전개 논리, 기관 간 협업 판단의 명료성, 완료근거/평가 연결, 훈련 활용성을 각각 1~5점으로 평가한다. 1점(대폭 수정 필요), 3점(일부 수정 필요), 5점(수정 거의 불필요)의 구체 예시를 사전에 합의한다.
- 먼저 독립 점수를 고정하고 평가자 간 일치도를 산출한다. 합의 점수를 만들 경우 최초 점수와 합의 근거를 함께 보존한다. CLI의 expert-review.csv는 입력 헤더만 제공한다.
- 훈련 참가자 성과 향상을 주장하려면 별도의 참여자 연구 설계와 적용되는 연구윤리 절차가 필요하다. 생성 품질 비교만으로 학습 효과를 주장하지 않는다.

## 분석과 논문 구성

예비실험은 조건별 분포·실패율·대표 오류 사례 중심으로 보고한다. 단일 사례의 반복 출력을 독립 사례로 취급해 유의성을 과장하지 않는다. 사례 수를 확장한 본 실험에서는 동일 사례·난이도·반복 블록의 대응 구조를 유지하고, 지표 유형과 실제 표본 크기에 맞는 분석법·신뢰구간을 사전에 정한다. 현재 문서에는 효과크기·p값·개선율을 기입하지 않는다.

논문은 서론 → 관련연구 → 지식모델과 생성·검증 방법 → 실험설계 → 실제 결과 → 한계 및 결론으로 구성할 수 있다. 관련연구 및 투고 학술지 양식은 별도 조사해야 한다. 현재 코드로 주장할 수 있는 기여는 관계 기반 입력, 공통 검증, 초안/보정 및 모델 이력 보존을 결합한 프로토타입의 설계·구현이다.

## 구현 검증 기록

Node.js v24.19.0에서 단위·통합·회귀 시험 35개를 실행하여 모두 통과했다. 별도 기존 골격 시험도 통과했다. `research/verify.mjs`는 중급 골격에 12개 결함을 한 번에 하나씩 주입해 같은 입력을 구버전/개선 검증기에 전달한다. 구버전은 3개, 개선 검증기는 12개를 탐지했고, 결함 없는 세 난이도 대조 입력은 모두 양쪽에서 통과했다. 결과 원자료는 `docs/research-verification.json`이다. 선택된 결함에 대한 구현 확인이며 일반화된 탐지 정확도나 AI 품질 개선율이 아니다.

비교 기준은 커밋 `e2c47b1e846261a95cd89e680190073667f3730e`의 생성기다. 재현 시 해당 커밋의 ontology 디렉터리를 별도 체크아웃하고 다음과 같이 경로를 지정한다.

```bash
node research/verify.mjs --baseline /path/to/baseline/ontology/src/scenario-generator.mjs --out research-runs/verification.json
```

이번 검증에서 실제 외부 AI 호출, 배포환경 검증, 전문가 평가는 수행하지 않았다. API 공급자 응답은 모의 전송으로 시험했다. 브라우저 실행 파일 확보 문제로 렌더링 기반 화면 검증은 완료하지 못했다.
