## 1. 현행 분석 (AS-IS 문제점)

### 1-1. 시뮬레이션 엔진
| # | 문제 | 위치 |
|---|------|------|
| A1 | **시드가 무의미** — `monteCarloSeed`를 저장·표시하지만 실제 샘플링은 `Math.random()` 사용. 같은 시드로 재현 불가 | `monteCarloSample()` (~L1688) |
| A2 | **피해가 정적** — 초기 1회 샘플 후 시간에 따른 피해 진행(확산) 모델 없음. 골든타임 개념이 텍스트로만 존재 | `ttxState.variables` |
| A3 | **기관 대응이 피해에 무영향** — 13개 기관 상태(대기→출동→투입→완료)가 바뀌어도 피해 변수는 그대로. 상태판이 장식에 가까움 | `ttxCycleStatus()`, `ttxAutoExecuteNonKey()` |
| A4 | **돌발변수 단순** — 발생 시 인명·이재민 일괄 +15% 고정. 재난유형·단계 무관 | `ttxSelectOption()` (~L2313) |
| A5 | **점수가 LLM 임의값** — 의사결정 점수를 LLM 응답의 `score`를 그대로 사용. 같은 선택도 매번 다른 점수 → 훈련 간 비교 불가 | `ttxSelectOption()` (~L2355) |
| A6 | **RTO 산출과 훈련 결과 미연동** — `monteCarloRTO()`의 dmg/res/dec factor가 훈련 중 의사결정 지연·돌발횟수와 연결 안 됨 | `monteCarloRTO()` (~L1720) |

## 2. 고도화 설계 (TO-BE)

### 트랙 1 — 시뮬레이션 엔진 정교화

**T1-1. 시드 기반 재현 가능 시뮬레이션** (A1 해결)
- `mulberry32` 계열 시드 PRNG를 내장하고 `monteCarloSample`·돌발판정·`monteCarloRTO`의 모든 난수를 이 PRNG로 교체
- 훈련 시작 시 시드 표시 + 시드 직접 입력 옵션 → 동일 조건 반복 훈련(사전/사후 비교 평가) 가능

**T1-2. 시간 진행 피해 모델** (A2, A3 해결)
- 훈련 타이머와 연동한 피해 진행: 매 시뮬레이션 틱(실시간 30초 = 재난시간 10분)마다
  `피해증가 = 기본증가율(재난유형별) × 단계계수 × (1 − 대응억제율)`
- **대응억제율 = 현장투입 기관들의 억제 기여 합** (기관별 기여도 테이블 신설, 예: 소방 0.25, 보건 0.15 …)
  → 기관을 빨리 투입할수록 피해 증가가 눈에 띄게 꺾임 = 상태판이 실제 게임 메커니즘이 됨
- 재난유형별 진행 곡선 차등: 홍수(선형↗), 산불·감염병(지수↗), 지진(초기 집중 후 여진 스파이크)

**T1-3. 규칙 기반 + LLM 혼합 채점** (A5 해결)
- 단계 점수 = `규칙점수 60% + LLM평가 40%`
- 규칙점수 요소: ①의사결정 소요시간(골든타임 내 가점) ②관련기관 적시 투입률 ③돌발 대응 여부 ④피해 억제 실적(초기 대비 증가 억제율)
- 동일 플레이 → 동일 규칙점수 보장, 훈련 회차 간 비교 가능

**T1-4. RTO-훈련 연동** (A4, A6 해결)
- `decFactor` = 1 + (의사결정 평균 지연 분 × 0.02), `dmgFactor` = 최종피해/초기피해 비율 등 훈련 실적을 factor에 직접 매핑
- 돌발변수 효과를 재난유형·단계별 차등화 (고정 15% → 유형별 테이블 + PRNG 변동)

**T1-5. 가변 국면·라운드 시스템** (고정 3단계 폐기 — C5 개정 반영)

*고정 3단계의 문제:* ①마지막 단계가 항상 최고조임을 참가자가 학습 → 예측 가능한 메타게임 ②대응을 잘하든 못하든 전개가 동일 → 의사결정의 전략적 무게 상실 ③훈련 강도 차이가 피해 수치 배율뿐 → 고급 훈련도 의사결정 3회로 끝. 실제 안전한국훈련 TTX도 상황부여 메시지 회수를 훈련 규모에 따라 유동 운영함.

*설계:*
- **국면(Phase)**: 재난 대응 생애주기 3국면으로 재정의 — ①초기대응(골든타임) ②확산·대응 ③수습·안정화. 화면 대구조는 유지(C5)하되 국면은 시간·성과 조건으로 전환
- **라운드(Round)**: 의사결정 단위. 국면당 1~3회 가변, 총 라운드 수는 강도별 차등 — 초급 3 / 중급 4~5 / 고급 6
- **성과 기반 전개 분기** (T1-2 피해 모델과 연동):
  - 피해 증가율이 임계 이하로 일정 틱 유지 → **조기 안정화**: 남은 라운드 축소 + 안정화 보너스 점수
  - 피해 폭주(초기 대비 배수 초과) → **위기 라운드 강제 삽입**: 최악 시나리오 대응 1라운드 추가
- **시나리오 생성 변경**: `phase1~3_event` 사전 고정 생성 폐기 → 시나리오 생성 시엔 국면별 "전개 아크(escalation arc)" 개요만 받고, 각 라운드 돌발상황은 직전 결정·현재 피해 수치를 반영해 즉석 생성 (T2-1 맥락 누적과 동일 프롬프트에서 처리 → 추가 API 호출 없음, C4 준수)
- **호환성**: `ttx_decisions.phase` 컬럼은 라운드 번호로 재사용(스키마 변경 없음, C3 준수). UI 배지 "n/3 단계" → "국면명 · 라운드 n/총N" 표시로 변경. 3단계 하드코딩 약 10곳(L612, L1669~1671, L1956, L2235~2252, L2410~2418 등) 일반화

### 트랙 2 — AI 시나리오 품질 향상

**T2-1. 맥락 누적 전달** (B1 해결) — *효과 대비 비용 최소, 최우선*
- `ttxState.decisions` 이력(단계·선택·결과 요약)을 선택지/결과 프롬프트에 포함
- 직전 `next_situation`을 다음 단계 상황 텍스트로 실제 반영 (현재는 initial_report 고정 표시)

**T2-2. 시나리오 Validator** (B2, B5 해결, 제약 C4 준수: 추가 호출 1회)
- 생성 직후 로컬 규칙 검증: 필수 필드, MC 수치 일치 여부, 글자수, 단계별 심각도 단조증가
- 규칙 위반 시에만 1회 재생성 요청(위반 항목을 피드백으로 첨부). 재실패 시 로컬 보정(수치는 MC 값으로 강제 덮어쓰기)

**T2-3. 선택지 다양화** (B3 해결)
- 위험도-라벨 고정 매핑 제거: 프롬프트에서 "위험도 조합은 매번 다르게, 정답이 명확하지 않게" 지시 + 렌더링 시 순서 셔플(PRNG)
- 선택지 스키마에 `related_agencies` 명시 → 결과 스키마에도 추가해 죽은 코드(B4) 부활

**T2-4. 지역 특성 반영 강화**
- 시나리오 프롬프트에 지역 입력값을 구조화(인구밀집/하천/산업단지/고령화 등 태그 선택 UI 추가)하여 전달, Validator에서 지역 태그 언급 여부 확인

### 트랙 3 — UI/UX·대시보드 고도화

**T3-1. 피해 추이 실시간 차트** (D1) — 순수 SVG 라인차트 (C2 준수)
- 상황판에 인명·이재민 2계열 스파크라인, 시뮬레이션 틱마다 갱신, 기관 투입 시점 마커 표시

**T3-2. 결과 리포트 시각화** (D2, D3)
- 의사결정 타임라인 (단계·선택·돌발·점수 흐름)
- RTO 몬테카를로 분포 히스토그램 (p50/p95 마커)
- 규칙점수 4요소 막대 분해 (어디서 감점됐는지 즉시 확인)

**T3-3. 상황 로그 개선** (D4)
- 유형 필터(의사결정/돌발/기관/시스템) + 중요 이벤트 하이라이트

## 4. 미결정 사항 (구현 중 확인 필요)

- 시뮬레이션 틱 환산비(실시간 30초=재난 10분)가 실제 훈련 운영 시간(통상 40~60분)에 맞는지
- 기관별 피해 억제 기여도 초기값 — 실무 경험 기반 보정 필요
- 규칙점수:LLM점수 = 6:4 비율의 적정성
- 강도별 총 라운드 수(초급 3 / 중급 4~5 / 고급 6)와 조기 안정화·위기 라운드 발동 임계값

## 5. v2.2 — 통합훈련 모드 (MSEL 기반 전개)

> 근거 문서: 2025년 괴산군 안전한국훈련 통합시나리오 / 2026 평가지표 2-1 토론기반 훈련
> 문제 인식: 라운드당 의사결정 1회 → 훈련이 10~15분에 종료. 토론기반 훈련인데 토론할 안건이 없음.

### 설계 원칙 (실제 통합시나리오 구조 반영)

실제 통합시나리오 = 단계 × 역할 매트릭스: ①환경 전개(강우·수위·교통) ②단계별 피해 누적
③단계별 주요쟁점(상황판단회의 안건) ④13개 협업기능별 조치 ⑤행안부 상황메시지 문제은행 참조.
DREX는 ②(피해 틱 모델)·④(기관 SOP)를 이미 보유 → ①③⑤를 추가한다.

### T4-1. 훈련 방식 선택 + 총괄표 골격 생성
- 1단계 폼에 훈련 방식: **통합훈련 모드(기본, 40~60분)** / 신속 모드(현행, 15~25분)
- 시나리오 생성 JSON 확장 (모드 무관 공통 생성, C4 준수 — 동일 호출):
  - `env_track[3]`: 국면별 {weather, hazard(수위·확산 등 위험지표), traffic, note}
  - `stage_issue_titles`: 국면별 쟁점 제목 2~4개 (라운드 메시지의 골격)
- Validator에 env_track·쟁점 검증 추가

### T4-2. 상황 메시지 시스템 (통합 모드)
- 라운드 시작 호출에서 쟁점 골격 + 직전 결정을 반영해 **메시지 2~4건**(초급2/중급3/고급4) 동시 생성
  — 각 메시지: 발신처·내용(수치 포함)·조치 2안(적정/차선, 관련기관 포함). API 호출 수 불변
- 도착: 라운드 시작 후 실시간 25초 간격 순차 도착 (회의 중에도 상황이 쌓이는 압박 재현)
- 처리: 조치 선택 → 관련기관 자동 출동 지령, 규칙 채점 (품질 70% + 적시성 30%)
- 미처리 메시지: 다음 라운드 진입 시 '미조치' 0점 + 상황일지 기록
- 신속성 채점 개편: 결정 소요시간 50% + 메시지 처리 적시성 50% (통합 모드)
- 평가점검표(2-1)·AI 보고서 근거에 메시지 처리 실적 포함

### T4-3. 환경 전개 트랙
- 현황판 상단: 현재 국면의 기상/위험지표/교통 카드, 국면 전환 시 갱신 + 상황일지 기록

### T4-4. 통합시나리오 총괄표 다운로드
- 훈련 종료 후 괴산군 양식 구조의 문서(HTML) 생성: 개요 / 총괄표(국면×환경·피해누적·쟁점) /
  회의 기록(라운드별 결정·메시지 처리) / 기관 운용 / 평가점검표(2-1) — 로컬 생성, API 호출 없음
- 효용: DREX가 훈련 도구를 넘어 통합시나리오 초안 작성 도구가 됨
